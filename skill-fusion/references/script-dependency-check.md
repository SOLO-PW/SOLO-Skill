# 脚本依赖解析与冲突检测

## 概述

跨 Skill 融合时，各 Skill 的 `scripts/` 可能引用不同依赖版本、同名脚本或隐含的运行时约束。直接合并脚本会导致依赖缺失、版本冲突或接口错配。本文件定义融合流程中对脚本的**解析 → 建图 → 冲突检测 → 解决 → 记录**五步方法，适用于 full 与 incremental 两种模式。

## 流程

```
步骤 1 依赖清单 → 步骤 2 依赖关系图 → 步骤 3 冲突检测 → 步骤 4 冲突解决 → 步骤 5 记录与验证
```

### 步骤 1：依赖清单

对每个输入 Skill 的 `scripts/`，为每个脚本提取：

| 维度 | 说明 | 示例 |
|------|------|------|
| 脚本名 | 文件名（含相对路径） | `data-format-csv.py` |
| 触发入口 | SKILL.md 中如何调用 | `python scripts/data-format-csv.py <in> <out>` |
| 外部依赖 | import / require / 三方库 | `pandas`、`requests` |
| 版本约束 | 显式或环境锁定的版本 | `pandas>=1.5`、`requirements.txt` |
| 返回值/产物格式 | 输入输出接口 | 输出 CSV / JSON |
| 运行环境 | Python/Node/Shell 及版本 | Python 3.10+ |

来源：脚本源码（import/require 语句）、同目录 `requirements.txt` / `package.json`、SKILL.md 中的调用说明。

### 步骤 2：依赖关系图

将所有脚本构成一张依赖关系图：

```
script-A.py ──依赖──▶ lib-X (v1)
script-B.py ──依赖──▶ lib-X (v2)、script-A.py
```

记录节点（脚本）与边（依赖），用于冲突定位与连锁影响分析。

### 步骤 3：冲突检测

逐节点检测以下四类冲突：

| 冲突类型 | 判定 | 严重级别 | 处理 |
|----------|------|----------|------|
| **版本冲突** | 同名依赖出现不兼容版本（broad 语义版本不一致） | 高 | 走冲突解决流程 |
| **同名冲突** | 两个 Skill 存在同名脚本，内容或接口不同 | 高 | 走冲突解决流程 |
| **依赖缺失** | 被引用依赖在融合结果中不存在或未声明 | 中 | 需补齐依赖声明 |
| **接口错配** | 脚本间调用参数/产物格式不匹配 | 中 | 标记并在合成时统一接口 |

同时检查增量场景：新脚本是否与基准已有脚本形成以上任意冲突。

### 步骤 4：冲突解决

遵循 [conflict-resolution.md](conflict-resolution.md) 的四级策略：

- **高**（版本冲突 / 同名冲突）→ 交互式解决，提供 4 选项（用 A 方案 / 用 B 方案 / 合并 / 条件分支）
- **中**（依赖缺失 / 接口错配）→ 提出统一方案（升级依赖、对齐接口、补齐声明），经用户确认
- 保留最健壮实现，弃用冗余脚本（同输出模板「资源整合策略」）

### 步骤 5：记录与验证

- 将每个脚本决策写入融合日志的「已解决冲突」或新增「脚本合并」条目
- 验证：所有保留下来的脚本依赖在融合结果中可解析、无未解决冲突
- 验证项列入 full 步骤 6 / incremental 步骤 6 的必备检查

## 融合日志记录示例

```html
<!-- 融合日志
来源 Skills: skill-a, skill-b
...
已解决冲突:
- [高] 脚本同名 conflict：csv_writer.py (skill-a) vs csv_writer.py (skill-b)
  → 用户选择：保留 skill-a 版本，弃用 skill-b 冗余脚本
- [中] 依赖缺失：project_export.py 依赖 pandas>=1.5，但融合结果未声明
  → 补充 requirements.txt
保留脚本:
- data-format-csv.py (来自 skill-a)
- project_export.py (来自 skill-b)
-->
```

## 与现有流程的衔接

| 位置 | 动作 |
|------|------|
| full 步骤 2 深度解析 | 提取脚本依赖（依赖清单） |
| full 步骤 3 关系分析 | 跨 Skill 脚本依赖冲突检测，并入冲突清单 |
| full 步骤 5 内容合成 | 按本方法整合脚本、保留最佳实现 |
| full 步骤 6 验证输出 | 校验脚本依赖可解析、无未解决冲突 |
| incremental 步骤 1 基准验证 | 继承基准脚本与已记录决策 |
| incremental 步骤 5 资源扩展 | 新脚本并入前执行本方法 |
| incremental 步骤 6 增量验证 | 复检新增脚本依赖与冲突状态 |
