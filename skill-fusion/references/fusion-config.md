# 融合配置（参数化）

## 概述

融合流程中使用多个数值阈值与约束。为避免把规则硬编码在 SKILL.md 与算法文档中，本文统一登记这些可配置项、默认值、作用范围与覆盖机制，适配不同规模、不同领域背景的融合任务。

所有硬编码限制在流程文档中均以「配置项」形式引用（如 `max_body_lines`），实际取值以本文件为准。

## 配置项登记表

| 配置项 | 默认值 | 作用范围 | 说明 |
|--------|--------|----------|------|
| `max_body_lines` | `500` | full 步骤6 验证 / 批量融合每轮检查 / 增量步骤6 | 融合后 SKILL.md body 行数上限，超出则拆分到 references |
| `max_skill_name_len` | `64` | 输出模板·命名规范 | 融合 Skill 名称长度上限（字符） |
| `overlap_high` | `0.50` | 交叉度评估 | 交叉度 ≥ 此值判为「高」 |
| `overlap_mid` | `0.20` | 交叉度评估 | 交叉度 ∈ [0.20, 0.50) 判为「中」；< 0.20 判为「低」 |
| `max_domains` | `4` | 批量融合复杂度预警 | 融合后领域数量 > 此值建议拆分 |
| `max_serious_conflicts` | `10` | 批量融合复杂度预警 | 严重/高冲突数 > 此值建议先解决冲突 |
| `max_complex_domains` | `3` | 阶段 6 复杂度检查 | 融合 Skill 涉及不同领域 > 此值考虑拆分 |
| `max_anti_pattern_domains` | `5` | 反模式警示 | 涉及领域 > 此值视为「复杂度爆炸」反模式 |
| `max_tuning_rounds` | `3` | 交互式调优 | 调优轮数上限 |
| `incremental_review_threshold` | `3` | 增量融合 | 累计增量 ≥ 此值建议整体审查；≥ 此值 +1（即 4 次）建议改 full 模式 |

## 覆盖机制

### 1. 输入覆盖

在「输入输出规范」的输入项中提供可选字段 `配置` 或 `配置覆盖`，用户可传入 JSON 风格的配置对象，覆盖任意配置项的默认值：

```json
{
  "max_body_lines": 800,
  "overlap_high": 0.60
}
```

覆盖规则：

- 未提供的配置项使用默认值。
- 传入值必须为正数（行数/字符数为整数，比率为 0-1 小数）；非法值回退默认值并在分析报告中标注。
- `overlap_high` 必须大于 `overlap_mid`。

### 2. 已有融合结果继承

增量融合时，从基准 Skill 的融合日志中读取并继承其配置覆盖；基准未记录的配置项使用默认值。若用户本轮另传配置，则以用户覆盖为准，并需在增量融合日志中记录配置变更。

### 3. 覆盖可追溯

任何非默认取值都必须在融合日志中记录，便于后续增量融合与审计追溯。

## 配置生效检查

| 检查项 | 说明 |
|--------|------|
| 一条规则全局一致 | 同一配置项在 SKILL.md 与算法/增量参考中指向同一取值来源（本文件） |
| 覆盖可解析 | 覆盖值通过合法性与跨项约束校验 |
| 增量可追溯 | 增量融合继承并记录配置，不静默改变基准取值 |
