# 冲突解决

## 概述

融合多个 Skill 时，冲突不可避免。本文档定义冲突分类体系、解决策略和交互式决策协议。

## 冲突分类

冲突分为四个严重级别：

| 级别 | 类型 | 描述 | 示例 |
|------|------|------|------|
| **严重** | 矛盾 | 同一任务的指令直接对立 | Skill A 说"使用 pdfplumber"，Skill B 说"使用 PyPDF2" 进行 PDF 提取 |
| **高** | 重叠 | 相同能力，不同实现 | 两个 Skill 都处理图片调整大小，但使用不同库 |
| **中** | 模糊 | 不清楚适用哪个 Skill 的方法 | 两个 Skill 都定义"验证"步骤但含义不同 |
| **低** | 冗余 | 重复内容，无冲突 | 两个 Skill 包含相同的 API 端点文档 |

## 解决策略

### 策略 1: 交互式解决（默认）

对**严重**和**高**级别冲突，始终询问用户。

**协议**：
1. 识别冲突并分类其严重级别
2. 清晰呈现冲突：
   - 每个 Skill 的说法/做法
   - 冲突原因
   - 每个解决选项的影响
3. 提供具体的解决选项：
   - **选项 A**：使用 Skill X 的方法（附理由）
   - **选项 B**：使用 Skill Y 的方法（附理由）
   - **选项 C**：将两种方法合并为统一方案（如可行）
   - **选项 D**：保留两种作为条件分支（由上下文决定最佳方法）
4. 等待用户决策后再继续
5. 在融合日志中记录决策

**向用户展示的示例提示**：
```
检测到冲突：PDF 文本提取方法
- Skill A (pdf-editor)：使用 pdfplumber 提取
- Skill B (pdf-analyzer)：使用 PyPDF2 提取
两种方法都有效。融合后的 Skill 应该使用哪种？
[选项 A] pdfplumber（更好的表格支持）
[选项 B] PyPDF2（更轻量的依赖）
[选项 C] 默认使用 pdfplumber，PyPDF2 作为备选
[选项 D] 让上下文决定（根据任务类型自动选择）
```

### 策略 2: 智能合并

对**中**级别冲突，统一方案可行时：

1. 分析两种方法找出共同点
2. 设计保留两者优势的合并方案
3. 向用户展示合并方案供确认
4. 如用户拒绝，回退到策略 1

**适用场景**：
- 两种方法从不同角度解决相同问题
- 组合方案严格优于任一单独方案
- 合并不显著增加复杂度

### 策略 3: 自动去重

对**低**级别冲突（纯冗余）：

1. 比较重复内容的完整性
2. 保留更全面的版本
3. 如版本有互补细节，静默合并
4. 无需用户交互

### 策略 4: 条件分支

当两种方法都有效但适用于不同上下文时：

1. 定义每种方法适用的明确条件
2. 用条件逻辑构建融合 Skill
3. 在 SKILL.md 中记录分支标准

**示例**：
```markdown
## 图片处理

照片：使用基于 OpenCV 的流水线（来自 skill-photo-editor）
矢量图形：使用 SVG 原生转换（来自 skill-svg-editor）
```

## 优先级规则

用户未指定偏好时，应用以下默认优先级规则：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 1 | **特异性** | 更具体的指令优先于一般指令 |
| 2 | **时效性** | 后提供的 Skill 优先（用户可能有意按此顺序提供） |
| 3 | **完整性** | 更全面的实现优先于部分实现 |
| 4 | **简洁性** | 功能等效时，更简单的方法优先 |
| 5 | **兼容性** | 兼容更多环境/工具的方法优先 |

## 用户交互模板

### 严重/高级别冲突模板

```markdown
## 冲突 #[编号]: [简短描述]

**严重级别**: [严重/高]

**涉及 Skill**:
- Skill A ([名称]): [描述其方法]
- Skill B ([名称]): [描述其方法]

**冲突原因**: [解释为什么冲突]

**解决选项**:

**[选项 A]** 使用 Skill A 的方法
- 优点: [优势]
- 缺点: [劣势]

**[选项 B]** 使用 Skill B 的方法
- 优点: [优势]
- 缺点: [劣势]

**[选项 C]** 合并两种方法
- 方案: [描述合并方式]
- 适用条件: [何时使用]

**[选项 D]** 条件分支
- Skill A 用于: [条件]
- Skill B 用于: [条件]

请选择（输入 A/B/C/D）：
```

### 中级别冲突模板

```markdown
## 冲突 #[编号]: [简短描述]

**严重级别**: 中

**涉及 Skill**:
- Skill A: [方法]
- Skill B: [方法]

**提议的合并方案**:
[描述合并后的统一方法]

**此方案的优势**:
- [优势 1]
- [优势 2]

是否接受此合并方案？（是/否）
- 是 → 使用合并方案
- 否 → 将转为严重级别冲突处理
```

## 冲突解决流程

```
检测冲突
    │
    ├── 严重/高 ──→ 交互式解决（询问用户）
    │       │
    │       └── 用户选择 ──→ 记录决策 ──→ 继续
    │
    ├── 中 ──────→ 尝试智能合并
    │       │
    │       ├── 合并成功 ──→ 用户确认 ──→ 继续
    │       └── 合并失败 ──→ 回退到交互式解决
    │
    └── 低 ──────→ 自动去重 ──→ 继续
```

## 融合日志

每个冲突解决必须记录在融合 Skill 的元数据中：

```markdown
<!-- 融合日志
来源 Skills: skill-a, skill-b, skill-c
已解决冲突:
- [严重] PDF 提取方法 → 用户选择 pdfplumber（来自 skill-a）
- [高] 图片调整算法 → 合并：照片用双线性，像素画用最近邻
- [中] 验证术语 → 统一为"质量检查"带子类型
- [低] 重复 API 文档 → 保留 skill-b 版本（更全面）
-->
```

此日志以 HTML 注释形式嵌入融合的 SKILL.md 中，用于可追溯性。

## 常见冲突模式及解决

### 模式 1: 工具选择冲突
**场景**: 两个 Skill 使用不同工具完成相同任务
**示例**: pdfplumber vs PyPDF2
**推荐策略**: 选项 C（默认 + 备选）或选项 D（条件选择）

### 模式 2: 工作流顺序冲突
**场景**: 两个 Skill 对相同任务有不同步骤顺序
**示例**: 先验证后处理 vs 先处理后验证
**推荐策略**: 选项 A 或 B，取决于哪个更合理

### 模式 3: 参数默认值冲突
**场景**: 相同功能但不同默认参数
**示例**: 图片压缩质量 80 vs 90
**推荐策略**: 选项 C（取中间值）或选项 D（按场景选择）

### 模式 4: 错误处理策略冲突
**场景**: 一个 Skill 严格失败，另一个 Skill 优雅降级
**示例**: 遇到错误立即停止 vs 记录警告继续
**推荐策略**: 选项 D（条件分支：严格模式 vs 宽松模式）
