# 文章生成指南

## 概述

本文档详细说明如何生成面向普通群众的开源项目推荐文章，用通俗易懂的语言介绍项目，不涉及技术细节。

## 核心原则

### 写作风格
- **通俗易懂**：避免技术术语，用日常语言
- **轻松有趣**：像朋友推荐好物一样
- **重点突出**：突出用户价值和实际效果
- **视觉友好**：多用emoji、图片

### 内容取舍
- ✅ **保留**：项目简介、功能亮点、使用场景、社区数据
- ❌ **删除**：技术栈表格、代码示例、API设计、项目结构

## 各部分生成指南

### 1. 标题生成

#### 格式
```
# [项目名称]：[一句话吸引人的描述]
```

#### 技巧
- 吸引眼球，突出核心价值
- 使用通俗语言，避免技术术语
- 让人一看就知道能用来做什么

#### 示例
- ✅ `QuantumOS：在浏览器里体验《流浪地球》的MOSS系统`
- ✅ `这个开源工具让你的照片秒变艺术画`
- ✅ `有了它，再也不怕忘记密码了`
- ❌ `基于React和TypeScript的高性能Web框架`（太技术化）

### 2. 项目简介生成

#### 格式
```markdown
## 🌟 这是什么？

[用2-3句话介绍项目是什么，能做什么，解决什么问题]
```

#### 技巧
- 用最简单的语言解释项目
- 突出能解决什么问题
- 让用户能快速理解项目价值

#### 转化示例
- 技术描述：`一个基于Next.js 14的App Router架构的Web应用`
- 通俗描述：`一个可以直接在浏览器里使用的酷炫系统`

- 技术描述：`使用IndexedDB实现数据持久化存储`
- 通俗描述：`你的数据会自动保存，刷新页面也不会丢失`

### 3. 亮点描述生成

#### 格式
```markdown
## ✨ 有什么亮点？

- **亮点1**：[用通俗语言描述，突出用户价值]
- **亮点2**：[用通俗语言描述，突出用户价值]
- **亮点3**：[用通俗语言描述，突出用户价值]
- **亮点4**：[用通俗语言描述，突出用户价值]
```

#### 技巧
- 转化技术特性为用户价值
- 突出用户能感受到的好处
- 使用生动形象的描述

#### 转化示例

| 技术特性 | 通俗描述 |
|----------|----------|
| Three.js 3D渲染 | 超酷的3D动画效果，看起来很科幻 |
| Framer Motion动画 | 丝滑流畅的动画，操作很跟手 |
| Zustand状态管理 | 数据实时同步，操作响应超快 |
| Tailwind CSS样式 | 界面好看又现代，看着就舒服 |
| IndexedDB存储 | 数据自动保存，不怕丢失 |
| WebSocket实时通信 | 实时更新，不用手动刷新 |

### 4. 场景描述生成

#### 格式
```markdown
## 🎯 能用来做什么？

- **场景1**：[具体的使用场景，让用户能想象到]
- **场景2**：[具体的使用场景，让用户能想象到]
- **场景3**：[具体的使用场景，让用户能想象到]
```

#### 技巧
- 具体化，让用户能想象
- 使用生活化的场景
- 突出实际应用价值

#### 示例
- ✅ `想做个炫酷的个人网站？用它就对了！`
- ✅ `需要管理一堆文件？它帮你整理得井井有条`
- ✅ `想体验科幻电影里的AI系统？这个能满足你`
- ❌ `适用于Web开发`（太笼统）
- ❌ `可用于前端项目构建`（太技术化）

### 5. 社区数据解读

#### 格式
```markdown
## 📊 大家都在用吗？

- ⭐ **受欢迎程度**：[Star数量 + 通俗解读]
- 🔥 **活跃程度**：[最后更新时间 + 通俗解读]
- 👥 **社区氛围**：[贡献者数量 + 通俗解读]
- 📜 **使用许可**：[许可证 + 通俗解读]
```

#### 通俗解读规则

**Star数量解读**：
- > 10000：`超火的项目，大家都在用！`
- > 5000：`非常受欢迎，口碑很好`
- > 1000：`很受欢迎，社区很活跃`
- > 500：`有不少人在用，评价不错`
- > 100：`新星项目，值得关注`
- < 100：`小众但有特色`

**活跃程度解读**：
- < 7天：`更新超活跃，维护得很好`
- < 30天：`定期更新，稳定可靠`
- < 90天：`偶尔更新，基本稳定`
- > 90天：`更新较少，但功能完善`

**社区氛围解读**：
- > 50人：`社区很活跃，有很多贡献者`
- > 20人：`有不错的社区支持`
- > 10人：`小团队在维护`
- < 10人：`个人项目，但很用心`

**使用许可解读**：
- MIT：`随便用，很自由`
- Apache 2.0：`商业使用也没问题`
- GPL：`开源免费，但修改也要开源`
- 其他：`使用前看看许可说明`

### 6. 体验方式生成

#### 格式
```markdown
## 🚀 怎么体验？

[提供最简单的体验方式，如在线演示、下载链接等]
```

#### 技巧
- 提供最简单的体验方式
- 优先推荐在线体验
- 如果需要安装，提供最简步骤

#### 示例
```markdown
## 🚀 怎么体验？

**在线体验**：直接访问 [在线演示](https://xxx.com) 就能玩！

**本地运行**（需要一点技术基础）：
1. 下载项目代码
2. 安装依赖
3. 启动就能用啦
```

### 7. 相关链接生成

#### 格式
```markdown
## 🔗 想了解更多？

- 📂 [项目主页](URL)
- 📖 [使用说明](URL)
- 💬 [交流社区](URL)
```

#### 技巧
- 使用亲切的语言
- 提供最有用的链接
- 不要太多，3-5个就够

### 8. 推荐理由生成

#### 格式
```markdown
## 💝 推荐理由

[用1-2句话总结推荐理由，像朋友推荐一样真诚]
```

#### 技巧
- 真诚自然，像朋友聊天
- 突出最打动人的点
- 不要夸大其词

#### 示例
- ✅ `如果你是《流浪地球》粉丝，一定要试试这个！在浏览器里体验MOSS系统，真的很酷！`
- ✅ `想找一个好用的文件管理工具？这个界面好看又实用，强烈推荐！`
- ❌ `这是一个功能强大、性能优越、架构先进的开源项目`（太官方）

## 常见问题处理

### 问题1：技术术语太多
**解决方案**：转化为用户能理解的语言
- 技术：`使用WebSocket实现实时通信`
- 通俗：`数据实时更新，不用手动刷新`

### 问题2：功能描述太技术化
**解决方案**：突出用户价值
- 技术：`支持文件CRUD操作`
- 通俗：`可以新建、编辑、删除文件，操作很方便`

### 问题3：亮点不突出
**解决方案**：找出最打动人的点
- 问自己：`这个项目最酷的地方是什么？`
- 问自己：`用户会因为什么而想试试？`

### 问题4：场景太笼统
**解决方案**：具体化
- 笼统：`适用于各种场景`
- 具体：`想做个炫酷的个人网站？用它就对了！`
