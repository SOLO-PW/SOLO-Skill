# README质量评估指南

## 概述

本文档说明如何评估GitHub仓库README文件的质量，用于生成推荐文章时的参考。

## 评估维度

### 1. 内容完整性（40分）

#### 基础信息（20分）
- [ ] 项目名称和描述（5分）
- [ ] 安装/使用说明（5分）
- [ ] 功能特性列表（5分）
- [ ] 贡献指南（5分）

#### 详细信息（20分）
- [ ] 架构说明（5分）
- [ ] API文档链接（5分）
- [ ] 示例代码（5分）
- [ ] 常见问题（5分）

### 2. 结构清晰度（30分）

#### 标题层级（15分）
- [ ] 使用H1作为主标题（5分）
- [ ] 使用H2作为主要章节（5分）
- [ ] 使用H3作为子章节（5分）

#### 内容组织（15分）
- [ ] 逻辑顺序合理（5分）
- [ ] 段落长度适中（5分）
- [ ] 使用列表和表格（5分）

### 3. 代码示例（20分）

#### 代码块（10分）
- [ ] 包含安装命令（5分）
- [ ] 包含使用示例（5分）

#### 代码质量（10分）
- [ ] 语法高亮正确（5分）
- [ ] 代码可执行（5分）

### 4. 视觉呈现（10分）

#### 图片和媒体（5分）
- [ ] 包含项目截图或Logo（3分）
- [ ] 图片清晰可读（2分）

#### 格式美化（5分）
- [ ] 使用emoji增强可读性（2分）
- [ ] 使用徽章显示状态（3分）

## 评分标准

### 优秀（80-100分）
- 内容完整，涵盖所有必要信息
- 结构清晰，易于阅读
- 包含可执行的代码示例
- 有项目截图或演示

### 良好（60-79分）
- 内容基本完整
- 结构较为清晰
- 包含基本的代码示例
- 有基本的视觉元素

### 一般（40-59分）
- 内容有缺失
- 结构较为混乱
- 代码示例不完整
- 缺少视觉元素

### 较差（20-39分）
- 内容严重缺失
- 结构混乱
- 缺少代码示例
- 几乎没有视觉元素

### 很差（0-19分）
- 几乎没有内容
- 无结构可言
- 无代码示例
- 无视觉元素

## 评估检查清单

### 必要元素检查
```
□ 项目名称
□ 项目描述
□ 安装说明
□ 使用说明
□ 许可证信息
```

### 推荐元素检查
```
□ 功能特性列表
□ 技术栈说明
□ 贡献指南
□ 问题反馈链接
□ 示例代码
```

### 加分元素检查
```
□ 项目截图/Logo
□ 架构图
□ API文档
□ 常见问题
□ 更新日志
□ 徽章（CI状态、版本号等）
```

## 评估流程

### 步骤1：检查必要元素
1. 是否有项目名称和描述
2. 是否有安装说明
3. 是否有使用说明
4. 是否有许可证信息

### 步骤2：检查内容结构
1. 是否使用标题层级
2. 是否有清晰的章节划分
3. 段落长度是否适中
4. 是否使用列表和表格

### 步骤3：检查代码示例
1. 是否有安装命令
2. 是否有使用示例
3. 代码是否有语法高亮
4. 代码是否可执行

### 步骤4：检查视觉元素
1. 是否有项目截图
2. 是否有Logo
3. 是否使用emoji
4. 是否有徽章

### 步骤5：计算总分
1. 根据检查结果计算各维度得分
2. 汇总得出总分
3. 确定质量等级

## 评估示例

### 示例1：优秀README
```markdown
# Project Name

[![CI](badge-url)](link)
[![Version](badge-url)](link)

> 一句话描述

![Screenshot](image-url)

## Features
- Feature 1
- Feature 2

## Installation
```bash
npm install project-name
```

## Usage
```javascript
const project = require('project-name');
project.doSomething();
```

## API
| Method | Description |
|--------|-------------|
| doSomething | Does something |

## Contributing
Please read [CONTRIBUTING.md](CONTRIBUTING.md)

## License
MIT
```

**评分**：
- 内容完整性：35/40
- 结构清晰度：28/30
- 代码示例：18/20
- 视觉呈现：9/10
- **总分：90/100 - 优秀**

### 示例2：一般README
```markdown
# Project

A project.

## Install

npm install

## Run

npm start
```

**评分**：
- 内容完整性：10/40
- 结构清晰度：15/30
- 代码示例：10/20
- 视觉呈现：2/10
- **总分：37/100 - 较差**

## 评估结果应用

### 在推荐文章中的体现

#### 优秀/良好
```markdown
- 📝 **文档质量**：优秀
```

#### 一般
```markdown
- 📝 **文档质量**：一般
```

#### 较差/很差
```markdown
- 📝 **文档质量**：较差
```

### 对文章生成的影响

#### 文档质量优秀
- 可以提取丰富的功能特性
- 可以生成详细的快速开始指南
- 可以提供准确的技术栈信息

#### 文档质量较差
- 功能特性可能需要手动补充
- 快速开始指南可能不完整
- 技术栈信息可能不准确

## 改进建议

### 对于文档质量较差的项目
1. 建议用户参考官方文档
2. 提示可能需要手动补充信息
3. 建议用户查看项目的其他资源（Wiki、Issues等）

### 对于文章生成
1. 根据文档质量调整文章详细程度
2. 对于文档质量差的项目，减少推测性内容
3. 提供更多占位符，提示用户补充
