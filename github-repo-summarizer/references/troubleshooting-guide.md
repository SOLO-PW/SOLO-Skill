# 常见问题处理指南

## 概述

本文档列出了在使用GitHub仓库推荐文章生成器时可能遇到的常见问题及其解决方案。

## 网络和访问问题

### 问题1：无法访问GitHub

**症状**：WebFetch请求失败，无法获取仓库信息

**可能原因**：
- 网络连接问题
- GitHub服务不可用
- 防火墙或代理限制

**解决方案**：
1. 检查网络连接是否正常
2. 确认GitHub服务状态（https://www.githubstatus.com/）
3. 尝试使用其他网络或VPN
4. 提示用户稍后重试

**处理话术**：
```
抱歉，目前无法访问GitHub。这可能是由于网络问题或GitHub服务暂时不可用。
请您检查网络连接后重试，或者稍后再试。
```

### 问题2：仓库不存在

**症状**：访问仓库页面返回404错误

**可能原因**：
- URL拼写错误
- 仓库已被删除
- 仓库是私有的

**解决方案**：
1. 检查URL是否正确
2. 确认仓库是否存在
3. 如果是私有仓库，提示用户提供访问权限

**处理话术**：
```
无法找到这个仓库。请检查：
1. URL是否正确拼写
2. 仓库是否仍然存在
3. 如果是私有仓库，您需要提供访问权限
```

### 问题3：私有仓库访问受限

**症状**：访问仓库返回403或404错误

**可能原因**：
- 仓库是私有的
- 没有访问权限

**解决方案**：
1. 使用AskUserQuestion询问用户如何处理
2. 提供选项：用户手动提供信息、使用公开信息、跳过

**处理话术**：
```
这个仓库似乎是私有的，无法直接访问。您希望如何处理？

选项：
1. 我提供信息 - 我会手动提供仓库的相关信息
2. 使用公开信息 - 仅使用公开可访问的信息生成文章
3. 跳过此仓库 - 跳过这个仓库
```

## 数据提取问题

### 问题4：README内容为空

**症状**：仓库没有README文件或README内容为空

**可能原因**：
- 项目没有创建README
- README文件名不是标准的README.md

**解决方案**：
1. 尝试访问其他可能的文件名（readme.md、Readme.md）
2. 使用仓库描述作为替代
3. 提示用户补充信息

**处理话术**：
```
这个仓库没有找到README文件。我将基于仓库的基本信息生成文章，
但内容可能不够丰富。您可以补充一些项目信息。
```

### 问题5：README内容过少

**症状**：README内容很少，无法提取足够信息

**可能原因**：
- 项目文档不完善
- 项目处于早期阶段

**解决方案**：
1. 使用AskUserQuestion询问用户是否补充信息
2. 使用占位符标记缺失内容
3. 尝试从其他来源获取信息（Issues、Wiki）

**处理话术**：
```
这个仓库的README内容比较简洁，可能无法生成详细的文章。
您是否希望补充一些项目信息，或者我使用现有信息生成文章？
```

### 问题6：无法提取功能特性

**症状**：README中没有明显的功能特性列表

**可能原因**：
- README没有功能特性章节
- 功能描述格式不规范

**解决方案**：
1. 从项目描述中推断功能
2. 从代码示例中提取功能
3. 使用占位符标记

**处理话术**：
```
未能从README中提取到功能特性列表。我将基于项目描述推断主要功能，
或者您可以手动提供功能列表。
```

### 问题7：图片链接失效

**症状**：README中的图片链接无法访问

**可能原因**：
- 图片链接已失效
- 图片使用相对路径
- 图片托管服务不可用

**解决方案**：
1. 尝试修复相对路径
2. 使用占位符图片
3. 提示用户提供图片

**处理话术**：
```
README中的图片链接似乎已失效。我将使用占位符图片，
您可以后续替换为有效的图片。
```

## 技术栈识别问题

### 问题8：无法识别技术栈

**症状**：无法从仓库信息中识别技术栈

**可能原因**：
- 仓库没有配置文件
- 使用非主流技术
- 文档没有提及技术栈

**解决方案**：
1. 从语言统计推断
2. 从文件扩展名推断
3. 使用AskUserQuestion询问用户

**处理话术**：
```
无法准确识别这个项目的技术栈。根据仓库信息，我识别到以下编程语言：
[语言列表]。您能否补充一下项目使用的框架和工具？
```

### 问题9：技术栈识别不准确

**症状**：识别到的技术栈与实际不符

**可能原因**：
- 关键词匹配误判
- 项目使用多种技术
- 文档信息过时

**解决方案**：
1. 使用AskUserQuestion确认
2. 提供识别结果让用户修正
3. 以用户确认为准

**处理话术**：
```
我识别到这个项目使用以下技术栈：
- 编程语言：[语言列表]
- 框架：[框架列表]
- 工具：[工具列表]

这些信息是否准确？如有误，请告诉我正确的技术栈。
```

## 文章生成问题

### 问题10：快速开始命令不确定

**症状**：无法确定项目的安装和运行命令

**可能原因**：
- README没有安装说明
- 使用非标准的构建工具
- 项目配置复杂

**解决方案**：
1. 根据技术栈推断标准命令
2. 提供通用的命令模板
3. 提示用户参考官方文档

**处理话术**：
```
无法确定项目的具体安装命令。我将根据技术栈提供通用的命令模板，
建议您参考项目的官方文档获取准确的安装说明。
```

### 问题11：适用场景难以推断

**症状**：无法从项目信息推断适用场景

**可能原因**：
- 项目描述过于简单
- 项目用途不明确
- 是通用工具类项目

**解决方案**：
1. 从技术栈推断通用场景
2. 使用AskUserQuestion询问用户
3. 提供占位符让用户补充

**处理话术**：
```
难以从项目信息推断具体的适用场景。您能否告诉我这个项目主要用于什么场景？
```

### 问题12：总结内容生成困难

**症状**：无法生成有说服力的总结

**可能原因**：
- 项目信息不足
- 项目没有明显亮点
- 难以找到推荐理由

**解决方案**：
1. 从Star数量、社区活跃度等方面总结
2. 从技术栈流行度总结
3. 使用通用的推荐理由

**处理话术**：
```
基于现有信息，我将从社区认可度、技术栈流行度等方面生成总结。
如果您有其他推荐理由，请告诉我。
```

## 输出格式问题

### 问题13：Markdown格式错误

**症状**：生成的Markdown格式有问题

**可能原因**：
- 特殊字符未转义
- 表格格式错误
- 代码块未闭合

**解决方案**：
1. 检查并修复格式问题
2. 确保特殊字符正确转义
3. 验证Markdown语法

**处理话术**：
```
生成的文章格式可能有问题。我将检查并修复Markdown格式问题。
```

### 问题14：中文显示问题

**症状**：中文字符显示异常

**可能原因**：
- 编码问题
- 字体不支持

**解决方案**：
1. 确保使用UTF-8编码
2. 检查字符是否正确显示

**处理话术**：
```
如果文章中的中文显示有问题，请确保使用UTF-8编码打开文件。
```

## 交互式提问问题

### 问题15：用户不回答问题

**症状**：用户忽略提问或回答不相关

**可能原因**：
- 问题不够清晰
- 用户不了解选项含义
- 用户希望快速完成

**解决方案**：
1. 使用更简洁的问题
2. 提供更清晰的选项说明
3. 使用默认选项继续

**处理话术**：
```
如果您没有特别的偏好，我将使用默认设置继续生成文章。
```

### 问题16：用户需求多次变更

**症状**：用户多次修改需求

**可能原因**：
- 用户不确定需求
- 需求理解有偏差

**解决方案**：
1. 确认最终需求
2. 总结已确认的需求
3. 按最终需求执行

**处理话术**：
```
让我确认一下最终的需求：
- 文章类型：[类型]
- 目标读者：[读者]
- 内容重点：[重点]

这样理解是否正确？
```

## 特殊情况处理

### 问题17：批量分析部分失败

**症状**：批量分析时部分仓库失败

**可能原因**：
- 部分仓库不存在
- 部分仓库是私有的
- 网络问题

**解决方案**：
1. 记录失败的仓库
2. 继续处理成功的仓库
3. 汇总报告失败原因

**处理话术**：
```
批量分析完成。成功：[数量]个，失败：[数量]个。

失败的仓库：
- [仓库1]：[失败原因]
- [仓库2]：[失败原因]
```

### 问题18：项目信息过时

**症状**：仓库信息很久没有更新

**可能原因**：
- 项目已停止维护
- 项目迁移到其他平台

**解决方案**：
1. 在文章中注明最后更新时间
2. 提示用户项目可能已停止维护
3. 建议用户查看最新状态

**处理话术**：
```
注意：这个项目最后更新于[日期]，可能已停止维护。
建议您在使用前查看项目的最新状态。
```

### 问题19：项目使用非标准结构

**症状**：项目结构不符合常规

**可能原因**：
- 使用非主流框架
- 自定义项目结构
- Monorepo结构

**解决方案**：
1. 尝试识别特殊结构
2. 提供通用的说明
3. 提示用户参考文档

**处理话术**：
```
这个项目使用了非标准的项目结构。我将提供通用的说明，
建议您参考项目的官方文档了解具体结构。
```

## 错误恢复策略

### 网络错误恢复
1. 等待几秒后重试
2. 尝试备用URL
3. 使用缓存数据（如果有）
4. 提示用户稍后重试

### 数据提取失败恢复
1. 尝试其他数据源
2. 使用默认值
3. 标记为待补充
4. 提示用户手动提供

### 格式错误恢复
1. 自动修复常见格式问题
2. 使用纯文本格式
3. 提示用户手动修复

## 用户反馈处理

### 收集反馈
```
文章已生成！如果您发现任何问题或有改进建议，请告诉我：
1. 哪些内容需要修改？
2. 哪些信息不准确？
3. 还需要添加什么内容？
```

### 处理修改请求
1. 确认具体修改内容
2. 评估修改可行性
3. 执行修改
4. 确认修改结果

### 记录问题
将常见问题记录下来，用于改进：
- 问题类型
- 发生频率
- 解决方案
- 用户满意度
