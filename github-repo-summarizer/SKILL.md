# 开源项目推荐文章生成器

## 概述

将GitHub仓库转化为通俗易懂的推荐文章，面向普通群众，用轻松有趣的语言介绍项目。

## 核心原则

- **通俗易懂**：避免技术术语，用日常语言
- **轻松有趣**：像朋友推荐好物一样
- **重点突出**：突出用户价值和实际效果
- **视觉友好**：多用emoji、图片

## 工作流程

### 步骤1：接收请求

从用户输入中提取：
- GitHub仓库URL（必须包含github.com）
- 文章风格（默认：轻松推荐）

**如果用户只提供URL，直接使用默认风格，无需提问。**

### 步骤2：获取信息

使用WebFetch访问仓库页面，提取：
- 项目名称、描述、Star数量
- 最后更新时间、许可证
- README内容、功能特性、图片

### 步骤3：转化信息

将技术信息转化为通俗语言：

| 技术特性 | 通俗描述 |
|----------|----------|
| 3D渲染 | 超酷的3D动画效果 |
| 实时同步 | 数据实时更新 |
| 离线支持 | 没网也能用 |
| 自动保存 | 不怕丢失 |
| 响应式 | 手机电脑都能用 |

### 步骤4：生成文章

按照以下结构生成：

```markdown
# [项目名称]：[一句话吸引人的描述]

![项目截图](图片URL)

## 🌟 这是什么？
[2-3句话介绍项目是什么，能做什么]

## ✨ 有什么亮点？
- **亮点1**：[用户价值]
- **亮点2**：[用户价值]
- **亮点3**：[用户价值]

## 🎯 能用来做什么？
- **场景1**：[具体场景]
- **场景2**：[具体场景]
- **场景3**：[具体场景]

## 📊 大家都在用吗？
- ⭐ **受欢迎程度**：[通俗解读]
- 🔥 **活跃程度**：[通俗解读]
- 👥 **社区氛围**：[通俗解读]

## 🚀 怎么体验？
[最简单的体验方式]

## 🔗 想了解更多？
- 📂 [项目主页](URL)
- 📖 [使用说明](URL)

## 💝 推荐理由
[1-2句真诚推荐]
```

### 步骤5：输出文章

保存为Markdown文件，提供computer://链接。

## 数据解读规则

### Star数量
- > 10000：超火的项目，大家都在用！
- > 1000：很受欢迎，社区很活跃
- > 100：新星项目，值得关注
- < 100：小众但有特色

### 活跃程度
- < 7天：更新超活跃，维护得很好
- < 30天：定期更新，稳定可靠
- < 90天：偶尔更新，基本稳定
- > 90天：更新较少，但功能完善

### 使用许可
- MIT：随便用，很自由
- Apache 2.0：商业使用也没问题
- GPL：开源免费，但修改也要开源

## 标题生成技巧

好标题示例：
- ✅ `QuantumOS：在浏览器里体验《流浪地球》的MOSS系统`
- ✅ `这个开源工具让你的照片秒变艺术画`
- ✅ `有了它，再也不怕忘记密码了`

坏标题示例：
- ❌ `基于React和TypeScript的高性能Web框架`（太技术化）
- ❌ `一个开源项目`（太笼统）

## 亮点描述技巧

转化技术特性为用户价值：
- 技术：Three.js 3D渲染 → 用户：超酷的3D动画效果
- 技术：IndexedDB存储 → 用户：数据自动保存，不怕丢失
- 技术：WebSocket通信 → 用户：实时更新，不用手动刷新

## 场景描述技巧

具体化，让用户能想象：
- ✅ `想做个炫酷的个人网站？用它就对了！`
- ✅ `需要管理一堆文件？它帮你整理得井井有条`
- ❌ `适用于Web开发`（太笼统）
- ❌ `可用于前端项目构建`（太技术化）

## 错误处理

### 网络错误
- 无法访问GitHub：`哎呀，网络好像有点问题，稍后再试试？`
- 仓库不存在：`这个链接好像不对，检查一下？`
- 私有仓库：`这是个私有项目，需要权限才能访问`

### 数据缺失
- README缺失：`项目介绍有点少，我根据能找到的信息写`
- 图片缺失：`没找到项目截图，用占位图代替`

## 质量检查

### 内容检查
- [ ] 没有技术术语
- [ ] 亮点突出明确
- [ ] 场景具体生动
- [ ] 数据解读通俗

### 风格检查
- [ ] 像朋友聊天一样自然
- [ ] 多用emoji，视觉友好
- [ ] 段落简短，易于阅读
- [ ] 真诚推荐，不夸大
