# 互联网缩写解析方法论

## 完整解析流程

```
用户输入 → 缩写识别 → 本地库查询
                              ├─ 命中 → 排序输出
                              └─ 未命中 → 搜索补充 → 验证 → 回填 → 输出
```

### 第一步：缩写识别

从文本中提取 2-6 个字母的单词，过滤常见英文单词，保留大小写不敏感匹配。

### 第二步：本地库查询

优先查询内置缩写库（150+ 词条），按置信度排序。支持多义性处理。

### 第三步：上下文/领域推断

自动从文本关键词推断领域（游戏/娱乐/科技/生活/动漫/金融），提升对应领域匹配权重。

### 第四步：搜索补充（关键步骤）

对本地库未收录的缩写，**必须执行搜索闭环**：

#### 4.1 生成搜索查询

调用 `search_slang.py` 或手动构造查询：
```
"{缩写}" 是什么意思 网络用语
"{缩写}" 缩写 全称 含义
```

有上下文时添加领域限定词：
- 游戏上下文 → `"{缩写}" 游戏术语 含义`
- 娱乐上下文 → `"{缩写}" 饭圈用语 含义`
- 科技上下文 → `"{缩写}" 技术术语 含义`

#### 4.2 执行搜索

使用 WebSearch 工具执行查询，收集搜索结果片段。

#### 4.3 解析搜索结果

从搜索片段中提取含义，支持以下模式：
- `"XX"是XXX的意思`
- `XX = XXX`
- `XX（XXX）`

#### 4.4 验证准确性

对搜索发现进行验证：
- **多来源一致** → 置信度 +15%
- **含义过于宽泛**（含"某个""一种"等）→ 置信度 -20%
- **含义过短**（<3字）→ 置信度 -10%
- **单一来源无上下文** → 保持默认 70%

#### 4.5 回填数据库

将验证后的搜索结果通过 `add_search_results()` 回填到数据库，供后续使用。

### 第五步：结果呈现

根据置信度排序输出，标注来源（builtin/web_search）。

## Agent 搜索闭环工作流

当 `decode()` 返回 `unknown` 列表非空时，agent 应执行以下步骤：

```
1. 检查 result['search_queries']，获取推荐的搜索查询
2. 对每个未知缩写，使用 WebSearch 执行查询（最多 2 次搜索/缩写）
3. 从搜索结果中提取含义（可手动分析或使用 parse_search_results()）
4. 验证准确性（使用 validate_findings() 或手动判断）
5. 调用 add_search_results() 回填到 decoder 实例
6. 向用户呈现最终结果
```

### 搜索预算控制

- **简单查询**（1-2 个未知缩写）：最多 2 次 WebSearch
- **中等查询**（3-5 个未知缩写）：最多 4 次 WebSearch
- **复杂查询**（5+ 个未知缩写）：优先搜索最常见的缩写，其余引导用户补充语境

### 批量搜索策略

多个未知缩写时，合并搜索：
```
# 好：一次搜索覆盖多个
WebSearch('"abc" "def" "ghi" 网络用语 缩写 含义')

# 差：逐个搜索
WebSearch('"abc" 是什么意思')
WebSearch('"def" 是什么意思')
WebSearch('"ghi" 是什么意思')
```

## 准确性保障机制

### 置信度分级

| 置信度 | 来源 | 可信度 | 处理方式 |
|--------|------|--------|---------|
| 0.95+ | 内置库/多源验证 | 高 | 直接输出 |
| 0.85-0.94 | 内置库/单源验证 | 较高 | 直接输出，标注领域 |
| 0.70-0.84 | 搜索发现/小众 | 中 | 输出并建议确认 |
| <0.70 | 模糊搜索/猜测 | 低 | 列举可能，引导用户确认 |

### 多义性处理

遇到多义缩写时：
1. 查阅 `ambiguous-abbreviations.md`
2. 按置信度排序展示所有可能
3. 根据上下文提升相关领域权重
4. 引导用户确认

### 错误处理

- **搜索无结果** → 引导用户提供上下文或直接询问对方
- **搜索结果矛盾** → 列举不同来源的说法，标注分歧
- **含义不确定** → 明确告知置信度低，建议用户验证
